What is new in 0.27.0, so far. With a new display design: update the firmware first, then the display design (Settings > Firmware > Check for updates).

**New**
- **A large clock on home** (`home.style: "clock"`): the time across the width, about twice as high as before --
  AM/PM beside it --, the date and the weather (an icon and the temperature) in a line under it, the shortcuts in
  one row; the status icons and the relays as on home. In the web interface: tap the clock in home's preview, *Home
  screen*. Needs the new display design (thanks ubi, forum #158).
- **Hardware buttons step through the swipe row**: `"open": "next"` and `"open": "previous"` bring the next page,
  or the one before, as a swipe does (thanks mife, forum #157). In the web interface: *Opens a page*, then *The
  next page* / *The page before*. A page can no longer have the id `next` or `previous`.
- **The screen woken from openHAB** (`display.screen.wake`): while an item is ON -- a motion sensor, a doorbell
  (a Contact: OPEN) -- the screen is on as if touched all the while, at night too; it dims after `idle_after` from
  when the item goes off. In the web interface: *Screen*, *On while an item is ON* (thanks ubeaut, forum #156).

- **A stop button on the media page** (`"stop": {"item": ...}`): a Switch, the player's stop channel (Sonos, Kodi,
  Squeezebox, Chromecast). While something plays, the play button shows a square and sends `ON` to it instead of
  pausing (a Player item knows no STOP). In the web interface: *Stop* on the media page (thanks ubeaut, forum #156).

- **Ask before a button switches** (`"confirm"` on a button, or on a group's button page for all of its tiles):
  `true` asks the standard question -- the button's label, "Switch on?", *Yes* / *Cancel* in the display language --,
  an object one's own: a title, a question, an icon, the buttons' labels and colour (`{label}` and `{to}` in its
  texts). Drawn by the panel, no new display design needed. In the web interface: *Ask first* in a tile's form
  (thanks Constantinos, forum #152).

- **openHAB's icons on the panel**: an item's icon in openHAB (its category, the classic icon set's names, also
  `oh:classic:...` and `iconify:mdi:...`) shows as the matching Material Design icon, changing with the state as
  openHAB's dynamic icons do -- a door open or closed, a battery's level, a light on or off. On a group's page every
  member shows its own (its metadata's `icon` first, the page's `icon` for one the panel does not know); elsewhere
  `"icon": "openhab"` takes it (status icons, shortcuts, home values, fixed rows, button tiles, weather cards), in the
  web interface the *openHAB* button beside their icon. The table:
  docs/openhab-icons.md.

- **A date near as "on"** (thanks riegelbrau, forum #165): a status icon or shortcut with a DateTime item can count
  as on while its date is near, `"on": {"within_days": 1, "from": "15:00", "until": "12:00"}` -- the bin icon shows
  from the afternoon before the collection until noon that day, hidden otherwise. `visible` takes the same. Until
  now a date item never counted as on, so "shown while on" never showed it. In the web interface: *On when*, *a date
  within days* -- chosen by itself for a DateTime item (that day; a condition chosen already stays). The icon field
  also says now when a name is no icon, a space at its end too (the panel drew nothing).

- **Line badges larger, and all as wide** (an entity row's `badge`, a feed's): a field of their own, reaching to
  the label, the characters about a third larger (in the style `rows` half as large again), and every badge of a
  page as wide as its widest, "1" as "M48" -- a column of line numbers (thanks mife, forum #157).

- **Another item's state in rules and `visible`** (as a sitemap's visibility): a status icon, a shortcut or a
  button shows only while another item is on, `"visible": {"item": "Burner"}`, or matches a condition
  (`{"item": "Power", "above": 100}`); a rule of `value_style` tests another item's state with an `"item"` of its
  own -- the heating's icon red or blue by its mode, shown only while the burner runs. In the web interface:
  *Shown only while the item*, and *Of the item* in a rule (thanks riegelbrau, forum #161).

**Changed**
- **Status, openHAB: its version and the protocol** -- "HTTP/1.1 over TLS 1.2" over https, as the NSPanel Pro's
  page shows them.
- **A touch clicks softly by default** (`display.sound.touch`: `click`, at the touch volume): a panel that had no
  touch tone set now clicks; `"touch": "none"` (*Touch: none* in the web interface) keeps it silent. It clicks as the
  finger is lifted, not as it comes down: swiping over a page of buttons no longer clicks (the keypad's keys still
  click as they are pressed).
- **The panel's https certificate is valid for 90 days** (was 820) and is issued anew 30 days before it runs out,
  by the panel's CA (or yours): the same key, so it costs the panel nothing. A panel issues its new one right after
  the update; a device that trusts the CA notices nothing, a browser where the certificate was only accepted asks
  again. A panel that was off past its certificate's end issues a new one as soon as its clock is set, not up to an
  hour later.

- **A list from one item (`feed`) without an answer** shows "No answer from openHAB" alone: the list before it
  (and its title) goes, since departures that look current would mislead (thanks mife, forum #157).
- **A list from one item that is broken JSON** shows "Invalid list (JSON)" instead of the JSON itself, where it
  broke in the log (*Diagnostics*, tag `feed`); so does an object without `rows`. A plain text (a rule's error)
  still shows as it is (thanks mife, forum #157).

**Fixed**
- **Progressive JPEGs as covers and pictures** (a Squeezebox server's covers): "a progressive JPEG, the panel
  decodes only baseline ones" -- now decoded by lowzag (MIT), scaled down as it decodes, its memory in PSRAM: about
  2 megapixels at most, a larger one refused after its first bytes. A baseline JPEG still goes to the ESP32's own
  decoder (thanks cd-tronic, forum #162).
- **Pictures decoded as they download** (JPEG and PNG): the file is never held whole, so the 400 KB limit is gone
  for them (a camera's full-size JPEG of 1 MB goes) and a picture takes less memory while it loads. An Image item's
  picture, which openHAB sends as text, still up to 400 KB.
- **Labels with a sitemap format**: an item made in openHAB's UI with a label the way of `.items` files,
  `Front door [%s]`, keeps the `[%s]` in its label word for word, and the panel showed it -- on an entity page's
  rows, in the cover group's table, in the item search. The panel now leaves a format at a label's end out, as
  openHAB's sitemaps do; the row shows the state itself anyway. A label you give in the panel's configuration is
  shown as you wrote it. (Thanks obones, issue #7; the cleaner way in openHAB is the item's *State Description*
  metadata, as riegelbrau wrote there.)
