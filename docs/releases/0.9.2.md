A memory leak fixed that could let a panel run out of memory over days, and more stack for the task that handles
WiFi events.

**Fixed**
- Each time the panel fetched an item's options, metadata or group members from openHAB, the memory they took was
  never given back. The panel fetches them at the start, when a page that shows them opens (a group, a cover, the
  favourites) and after reconnecting to openHAB. A fetch lost from a few KB up to tens of KB, depending on the item:
  most with large metadata, such as a catalogue with logos. A panel that reconnects often (a weak WiFi link) or whose
  pages are opened a lot lost memory step by step, until a restart. The memory is now freed after every fetch.
- The task that handles WiFi and network events (ESP-IDF's `sys_evt`) had the default 2304 bytes of stack and used
  about 1.5 KB of it, more on paths that run rarely, such as falling back to the setup network. A stack overflow
  there restarts the panel; it now has 4096 bytes.

**Install**
- Already running OHpanel: Settings > Firmware with `ohpanel-nspanel-eu-firmware-0.9.2.bin` from `ohpanel-0.9.2.zip`.
  The display design (`ohpanel-nspanel-eu-display-bc629e1e.tft`) is unchanged.
- First installation over the serial port: [docs/install.md](https://github.com/bruestel/ohpanel/blob/main/docs/install.md),
  or in the browser: https://bruestel.github.io/ohpanel/flash/
- Coming from Tasmota or Sonoff's firmware: flash the factory image over the serial port, flash erased first. An
  update from Tasmota over WiFi keeps Tasmota's partition table, in which OHpanel cannot store its configuration.
- `ohpanel-0.9.2.zip` holds the factory image (serial, offset 0), the firmware for updates over WiFi, the display
  design `bc629e1e` and the licences that go with the binaries.
