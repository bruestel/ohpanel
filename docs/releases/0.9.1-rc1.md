A test build for [#1](https://github.com/bruestel/ohpanel/issues/1): the display design could not be written to a
display that still runs Sonoff's own design (a panel from the shop, or one that ran Tasmota).

**Fixed**
- Sonoff's design runs the display in protocol reparse mode, where it executes no command and answers only with
  buffer overflows (status 0x24). OHpanel now asks it to leave that mode, when looking for the display and before
  writing the display design.
- Writing the display design took any byte from the display as the confirmation of a block, the 0x24 overflows too:
  the upload "succeeded" while nothing was written. Only the confirmation itself (0x05) counts now; anything else
  ends in an error that says what the display answered.

**Install**
- Already running OHpanel: Settings > Firmware with `ohpanel-nspanel-eu-firmware-0.9.1-rc1.bin` from
  `ohpanel-0.9.1-rc1.zip`, then write the display design again (`ohpanel-nspanel-eu-display-bc629e1e.tft`, unchanged).
