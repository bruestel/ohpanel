Writing the display design now works on a panel that comes from the shop or from Tasmota
([#1](https://github.com/bruestel/ohpanel/issues/1)), and the front buttons no longer wake a screen that is off.

**Fixed**
- The display design could not be written to a display that runs Sonoff's own design. The firmware that ran before
  (Sonoff's, or Tasmota's NSPanel driver) puts the display in protocol reparse mode, where it executes no command and
  answers only with buffer overflows (status 0x24), and Sonoff's design keeps that mode across restarts. OHpanel now
  asks the display to leave it, when looking for the display and before writing the display design, and switches the
  display off and on before every upload.
- Writing the display design took any byte from the display as the confirmation of a block, the 0x24 overflows too:
  the upload "succeeded" while nothing was written. Only the confirmation itself (0x05) counts now; anything else
  ends in an error that says what the display answered.

**Changed**
- At night (or idle at 0 %) the screen stays off when a front button is pressed: the button switches as always, a
  touch on the screen still wakes it.

**Install**
- Already running OHpanel: Settings > Firmware with `ohpanel-nspanel-eu-firmware-0.9.1.bin` from `ohpanel-0.9.1.zip`.
  The display design (`ohpanel-nspanel-eu-display-bc629e1e.tft`) is unchanged.
- First installation over the serial port: [docs/install.md](https://github.com/bruestel/ohpanel/blob/main/docs/install.md),
  or in the browser: https://bruestel.github.io/ohpanel/flash/
- Coming from Tasmota or Sonoff's firmware: flash the factory image over the serial port, flash erased first. An
  update from Tasmota over WiFi keeps Tasmota's partition table, in which OHpanel cannot store its configuration.
- `ohpanel-0.9.1.zip` holds the factory image (serial, offset 0), the firmware for updates over WiFi, the display
  design `bc629e1e` and the licences that go with the binaries.
