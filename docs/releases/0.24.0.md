Lists and the weather from one item a rule writes, line badges for buses and trains, a tap on the clock or a hardware
button that opens a page, faster details from openHAB, and numbers from older openHAB versions rounded as they
should be. With a new display design: update the firmware first, then the design.

**New**
- **A list from one item** (`"feed": {"item"}` on an entity page, in place of `rows` or `group`): a rule writes the rows
  as JSON to a String item -- departures, waste collection, anything an API gives. As the page opens the panel sends
  the item `refresh` and shows "Loading..." until the list comes; with `"refresh": 60` it asks again while the page
  shows. Only rows that changed are drawn again. No answer within `timeout`: "No answer from openHAB" above the list.
  `{"title", "note", "rows"}` brings a title of its own ("Departures 14:02") and a note above the rows. The docs
  have a rule that fetches and caches.
- **Line badges** (`"badge": "S12"`): one to three letters and digits on a band of the icon's colour, in place of a
  row's icon on the entity pages -- in a fixed row, a list's row, or a group member's metadata. The web editor chooses
  between an icon and a line badge and shows the badge as the display draws it.
- **The weather from one item**: a weather page's `"feed": {"item", "codes"}` takes its days from JSON a rule writes
  (`{"days": [{"date", "max", "min", "icon", "condition", "extras"}], "now": {"temp"}}`), and home's
  `"weather_feed"` today's icon, high, low and the temperature now. Days before today are left out. The docs have rules
  for the Bureau of Meteorology's forecast and for the Open-Meteo binding's time series; a new icon set `bom` takes
  BOM's `icon_descriptor`.
- **A tap on the clock or the date** opens a page (`home.clock_page`), e.g. the departures.
- **A hardware button that opens a page** (`"open": "<page>"` on `home.relays[n]`): a press wakes the screen and shows
  the page; the relay is left alone or follows an item of its own.
- **Fixed rows show openHAB's label**: a row without a `label` of its own shows its item's label from openHAB, not its
  name; a label changed in openHAB shows when the page opens again.
- **Faster details from openHAB**: options, labels, group members and commands resume the TLS session of the request
  before instead of a full handshake each time (0.2 s instead of up to 2.7 s).
- **A configuration saved elsewhere is not undone**: a web page left open since asks before it overwrites what
  another browser, or the panel itself, saved in between.

**Fixed**
- **A tap on an empty spot wakes a dimmed screen** (home, the settings, the volume): before, only something with an
  action did.
- **The weather icon of a code with decimals**: Open-Meteo's `3.0` showed N/A; a code the icon set has as a whole
  number now counts as that number.
- **Numbers from older openHAB versions** (without `numericState` in their events): the panel showed openHAB's text as
  it was ("8.6 °C", the low and high cut to "4.0..."), `decimals` did nothing, a colour temperature in Kelvin was taken
  for percent and a thermostat's target went without its unit. The number and its unit are now read from the state.
- **The display preview** draws the clock and AM/PM, OHpanel's own icons and the line badges where the display does.

**Docs**
- Switching a relay from openHAB or with curl, and a relay as a momentary switch with `expire`.
- How much room long weekday and month names have in the home screen's date.

The display design changes for every variant: Settings > Firmware > Check for updates installs the firmware, then the
display design it offers.
